# MX60 Internal Review Log — template

**The working channel for comments on the Living Draft**, until Parametrix assigns a document owner
and a review process under **D-1**. Copy this file, or the table alone, into wherever the review is
actually being held.

> **Why a log and not an email address.** There is no document owner to send comments to, and
> naming one would invent a Parametrix arrangement that does not exist. A log has a second
> advantage: a reviewer can see what someone else has already raised, and add to it instead of
> repeating it.

## How to enter a comment

**Identify the document and the section.** `Field How To §17.3`, `Office How To §31`, `SOP D-13`,
`Manual §21.4`, `W-08`. A comment that does not say where it applies cannot be actioned, and will
come back to you asking where.

**Say which of the four questions it answers**, if it answers one:

| | |
|---|---|
| **Q1** | Is anything technically wrong? |
| **Q2** | Is anything impractical in actual field or office use? |
| **Q3** | Is anything presented more strongly than Parametrix has actually decided? |
| **Q4** | What would prevent you from performing the work using these documents? |

**A gap is a valid comment.** "I could not do X from this" is more useful than a correction.

### Disposition values

| Value | Meaning |
|---|---|
| **Open** | Not yet looked at |
| **Accepted** | Will be changed. The Working Version it lands in goes in the last column |
| **Changed** | Done, and circulated |
| **Declined** | Not changing it, **with the reason in the log**. A declined comment stays visible |
| **Register item** | The comment is a decision, a test or a vendor question. It gets a `D-`, `T` or `V-` number in `master-register.csv` and is tracked there instead |

> **The last row matters most.** A comment that becomes a register item is not closed — it is
> re-homed into the one place where open items are tracked, so it cannot be lost between a review
> log and a document.

## What this log is not

**It is not a defect tracker for the equipment or the software.** A TBC bug or an MX60 fault goes to
Trimble, and — if it changes what these documents say — comes back here as a `V-` item.

**It is not an approval record.** Nothing in this log approves anything. The Living Draft is
**Not approved — Living Draft** and stays that way until Parametrix decides otherwise.
